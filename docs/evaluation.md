# Evaluation

The evaluation scenarios are defined in ADR 0015. They were run on 2026-10-30 with:

```powershell
python scripts\run_evaluation.py
```

Every scenario runs through the real orchestrator and is tagged in LangSmith as `eval:<name>`. Two modes are used:

- **Live:** real Gemini, PubMed and embeddings. Used for Q2, Q3 and the consistency check, for the Critic replay in row 6, because a fake Critic would test nothing, and for one eligibility call on the injection record in row 16b.
- **Mock:** fake LLM, PubMed, embedder and Gmail clients, tagged `mock=true`. Only the network call is faked. Retries, throttling, validation, routing and the send gate run for real.

**No scenario sent a real email.** Live runs rejected at review, and their Gmail factory raises if it is ever called. The real delivery is the separate row 13b, run by hand.

**Gemini requests:** 48 for the live scenarios (Q2 11, Q3 14, row 6 1, row 16b 1, consistency 21) and 0 for the mocked ones.

**Evidence:**
- `evidence/evaluation-results.json`: the checks and details for every row
- `evidence/traces/`: the 4 traces exported from LangSmith for row 18
- `evidence/eval-runs/`: the run file of every scenario
- `evidence/eval-normal-synthetic-review.txt` and `evidence/eval-normal-pubmed-review.txt`: the review screens of the live Q2 and Q3 runs
- `evidence/eval-normal-synthetic-q1-review.txt`: the review screen of a live brief Q1 run (run 20261030-090021-d33b, 11 Gemini requests, rejected, nothing sent), run separately from the table below as the cited answer to Q1. Its run file is in `evidence/eval-runs/`.

**Status:** 18 PASS (including the real sends, row 13b, the live injection test, row 16b, and the secrets check, row 18), 1 PARTIAL and 1 FAIL. The lesson-learned column is a **DRAFT** to be rewritten.

## Notes

- **What mocked rows test:** routing, retries, error classes, the send gate and the output, not model quality. Model quality is tested by the live rows: 1, 2, 6, 16b and 17.
- **What row 2 does not test:** whether the summary is correct for this question. Run-to-run variation is in build-notes and the README limitations.
- **The rows that did not fully pass:** row 6 (FAIL) and row 16a (PARTIAL, the simulated worst case; real Gemini did not obey in row 16b) are known limitations, recorded honestly in the README. No code change was made to hide either.
